# GitHub publication

Suggested repository name: `customercare-ai`

Suggested description: `n8n complaint triage with AI classification, Google Sheets tracking, Gmail drafts, and priority escalation.`

Suggested topics: `n8n`, `customer-support`, `workflow-automation`, `ai-agent`.

1. Connect GitHub in the app and choose the destination owner and repository. A private repository is a useful first review location; choose visibility deliberately.
2. Publish only the contents of this repository folder. Do not upload the original workflow export, local work directory, execution histories, or account credentials.
3. Use a GitHub privacy email for commit attribution if personal identifiers should not appear in public commit history. Repository ownership still reveals the chosen account or organization.
4. Run the included validator and inspect the final staged files before committing.
5. Confirm setup steps with a separate n8n import, then document the n8n version and actual test results.
6. Choose a license if you intend to grant reuse rights. No license has been assumed.

The earlier starter files must be supplied separately before they can be reviewed or merged. The initial sanitized package is being published to `Bakkar404/customercare-ai` as a public repository on 2026-10-26.
